## Three decisions worth keeping

**1. An HTML version was written unasked, and it was the right call.** The owner asked for Markdown
because Ryan pastes into "the code version of the WYSIWYG editor". If that is the HTML source view,
pasted Markdown renders as raw text with visible `##` and pipes, and the 9-row comparison table
breaks worst. Both formats now exist. Told him to use the `.md` if Ryan's editor is actually a
Markdown box, and to delete the H1 line if the CMS supplies its own title field.

**2. The FAQ shipped WITHOUT FAQPage JSON-LD, on purpose.** Owner approved a 6-question FAQ
(permit, bad-credit/no-credit-check, foundation, HOA, early payoff, lifespan). Written as plain
H2/H3 only. VRTO controls its own schema layer and a second FAQPage block could conflict with what
their template already emits. Two answers are written to the standing compliance rules rather than
to what converts: the permit answer puts responsibility on the BUYER, and the credit answer states
that an independent third-party administrator reviews EVERY application and approval is never
guaranteed. The HOA answer ends by sending the reader to the shed, which is true and is what keeps
VRTO's neutral editorial standard intact.

**3. GOOGLE PREFERRED SOURCES: RECOMMENDED AGAINST.** Owner asked about the SEJ writeup. It is a
news/Top-Stories feature that only works once a human reader clicks a button to favour you in their
own results. It is not a ranking boost. SBD's own GSC data is 15 clicks in 28 days, so there is
nobody to press it, and the cost is a third-party Google script on a fast Cloudflare Pages site.
The tempting counter-argument, that it feeds AI Overviews and AI Mode and therefore the AEO play,
does not survive: it amplifies for people who already chose you, it does not win the citation.
Offered the zero-code fallback (the deeplink `https://www.google.com/preferences/source?q=steelboxdirect.com`
in an email signature or GBP post) and a 30-second test: open the deeplink and see whether the
domain appears in the tool at all.

## The near-miss of the day: a metadata leak in the file he was about to send

The owner supplied a Gemini hero, which was sanitized per the 2026-06-22 farming-images procedure
(`exiftool -all=`, original untouched, C2PA/SynthID JUMBF blocks confirmed gone). He then asked
whether his **Photoshop re-save** still carried a SynthID pixel watermark.

- **On SynthID:** it cannot be verified here. No local tool detects it and only Google's own
  detector can. Said so rather than guessing. The evidence that does exist: a pixel diff against
  the raw Gemini file returned mean absolute difference 0.75/255, max 15, and 0.001% of pixels
  differing by more than 8. That is JPEG re-encode noise, not an edit. SynthID survives rougher
  handling than that, so treat the watermark as still present.
- **The finding that mattered more:** the Photoshop re-save was NOT clean. It had shed the C2PA
  block, but Photoshop wrote its own trail in its place: `Adobe Photoshop 27.7 (Macintosh)` as
  Creator Tool and Software, XMP Document/Instance/Original-Document IDs, a history entry, an
  embedded 5,330-byte thumbnail, and same-day timestamps. Attaching that to an email to Ryan would
  have sent his Photoshop trail with it. Flagged unprompted; owner approved; stripped and
  overwritten. Tag dump is now JPEG structure only. sha1 `968c3e51`.

**RULE OUT OF THIS, now recorded in the prompts file:** sanitise the file that will actually be
SENT, and do it LAST. Sanitising the file that was GENERATED is worthless if any editor touches it
afterward.
