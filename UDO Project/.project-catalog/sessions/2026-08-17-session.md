## The new thread, T-141: FreedomConex has published geo-based pricing

`https://www.freedomconex.com/shop`, backed by `https://www.freedomconex.com/api/pricing?zip=NNNNN`.

**The orchestrator pulled the API across six ZIPs rather than theorising about it**, and the data reshaped
the question three times over.

1. **Their used grade is literally the string `WWT`.** Not a synonym. So publishing used pricing requires
   ZERO change to the WWT-only condition decision locked on 2026-06-09 with the sales lead. Only NEW is a
   genuinely new catalogue item, and it is cleanly separable.
2. **Unit price is regionally stable; DELIVERY is the variable.** In-region used unit prices spread about
   3.5 percent while `baseDeliveryCost` ranges $550 to $1,162, hitting $1,457 when a SKU sources from
   Detroit rather than Cincinnati. **This is the answer to the owner's stated needle.** Publish the stable
   unit price and make delivery the explicitly named variable, so the call to Doug is genuinely necessary
   rather than a sales gate dressed as service.
3. **The API independently corroborates the HC-below-Standard anomaly**, which had rested on the owner's
   say-so since 2026-07-09 behind a code comment reading "owner-confirmed, not a typo". Cincinnati used
   40-hc $1,749.30 is genuinely below used 40-std $1,852.20.

The API is public and unauthenticated, so the owner's idea of asking Doug for access was unnecessary. It
also exposes FC internal identifiers, `deliveryDriverId` and location UUIDs, which is worth telling Doug.

## The question the build now turns on, raised and NOT guessed

Answer 3 has two readings roughly $600 a container apart, which on the 20ft is 30 percent.

| Cincinnati, used WWT | FC unit | FC delivery | Delivered | Site publishes |
|---|---|---|---|---|
| 20ft std | $1,440.60 | $600 | $2,040.60 | $2,010 |
| 40ft std | $1,852.20 | $591 | $2,443.20 | $2,710 |
| 40ft HC | $1,749.30 | $591 | $2,340.30 | $2,470 |

Mirroring the **delivered** figure preserves the existing "a real, all-in number" framing and moves prices 1
to 10 percent. Mirroring the **unit** figure cuts the headline 20ft by 28 percent and makes the live all-in
language false by about $600, producing exactly the price-mismatch-at-contact failure already identified as
the real risk. The API field is named `fromPrice` and equals the unit price with `baseDeliveryCost` returned
separately, so FC is probably displaying the unit figure, but that was NOT treated as settled.

**Orchestrator recommendation: publish both.** Unit as the headline, because it is the number FC shows, it is
regionally stable, and it is what wins price comparisons and AI citations; then the delivery line and the
delivered total once a ZIP is known. The API returns both per ZIP. Cost: the all-in language changes across
the homepage price section, product hub, spec pages, homeowners and businesses.

## The competitive finding

**FC's own shop is a client-rendered app with no price in its HTML.** Fetched and confirmed. So FC will not
earn price rich results or AI price citations on its own numbers. A build-time harvest puts SBD ahead of its
own supplier on the supplier's prices, which is the AEO play this project already runs, handed over for
free.

## Two practical constraints named early

**Cloudflare Pages has no native cron**, so the 5am job needs GitHub Actions, and this project has already
hit that wall: `supabase-keepalive.yml` is still untracked locally because the `gh` token lacks `workflow`
scope. The workflow may have to be created through the GitHub web editor.

**Actions cron is UTC**, so 5am Eastern is 09:00 or 10:00 depending on DST. Recommend pinning 10:00 UTC and
accepting 6am in summer rather than letting the job drift an hour twice a year.
