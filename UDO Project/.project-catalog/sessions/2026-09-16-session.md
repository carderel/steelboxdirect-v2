## New standing rule: pre-push SEO gate (owner-requested)
- `scripts/pre-deploy-seo-scan.mjs` scans **dist/, never src/**, for hidden text (inline opacity
  <0.3, font-size <10px, far off-screen) and lazy above-the-fold images.
- `scripts/pre-push-gate.sh` wraps it as a PreToolUse hook on `git push` in `.claude/settings.json`
  (existing UDO hooks preserved, validated with `jq -e`).
- **Hidden text DENIES the push.** A missing `dist/` also denies: you cannot review output you have
  not built. A clean scan ALLOWS but injects a standing rule requiring an SEO agent to have reviewed
  the rendered output for this build.
- **Why lazy images only warn:** blocking on them produced 13 findings, 12 legitimate (blog
  thumbnails, a QR code). A lazy thumbnail and a lazy hero are identical markup, so it cannot be
  decided mechanically. A gate that cries wolf gets bypassed. The script holds the floor; the review
  makes the judgement call.
- Also fixed by testing: "first image = hero" is wrong here, the header logo is always first.
- Proven both ways with real hook payloads: clean build allows, reinjected hidden text denies.
- **Gate bug caught and fixed immediately:** `if: "Bash(git push*)"` is malformed, so it was ignored
  and the hook ran the full scan on EVERY Bash command. Correct syntax is `Bash(git push:*)`.
  Proven both ways: a plain command fires nothing, `git push --dry-run` fires the gate.
